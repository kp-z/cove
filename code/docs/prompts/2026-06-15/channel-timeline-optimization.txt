==================== 信息架构 ====================

6 大信息维度（根据消息类型条件显示）：

[1] 基础信息（所有消息）
  - 显示：ID、状态、类型、时间、是否编辑
  - 数据字段：message_id、status、content_type、created_at、is_edited

[2] Agent 执行（仅 Agent 消息）
  - 显示：执行模式、状态、时长、thinking（可展开）、工具调用列表
  - 数据字段：agent_execution_metadata（可能不存在，需空值检查）
  - 工具图标：✓ success | ✗ error | ⟳ running | ⏸ pending

[3] 性能指标（仅 Agent 消息）
  - 显示：模型、tokens、缓存、延迟、成本
  - 数据字段：agent_execution_metadata.usage
  - 格式化：tokens 千位分隔符、百分比 1 位小数、成本 4 位小数

[4] 关联信息（有数据时显示）
  - 显示：Mentions、references、线程、反应
  - 数据字段：mentions、references、thread_id、reactions

[5] 系统事件（仅 system 消息）
  - 显示：类型、级别、消息、metadata、stack
  - 数据字段：systemDetails

[6] 编辑历史（已编辑消息）
  - 显示：时间、编辑者、历史内容
  - 数据字段：edit_history（按时间倒序）

==================== 开发规范 ====================

KISS 原则：
  - 不要过度抽象，保持简单直接
  - 不要猜想数据结构，基于实际数据开发
  - 不要添加需求外的功能

高内聚低耦合：
  - 每个 Section 组件只负责自己的信息维度
  - 组件间不互相依赖
  - 格式化函数独立到 utils/format.ts

TypeScript：
  - 严格类型，避免 any
  - 使用 ?. 可选链访问嵌套属性
  - 参考 message.types.ts 类型定义
  - 不要猜测类型，查看实际定义

React：
  - 函数组件 + Hooks
  - 子组件用 React.memo 包裹
  - 条件渲染，默认折叠不渲染展开内容

数据传递：
  - 在 CompactTimelineNode props 添加 messageData?: MessageEntityJSON
  - 检查 useTimelineNodes 是否传递完整数据
  - 所有嵌套字段用 ?. 访问
  - 不要假设数据存在，先验证再使用

格式化：
  - Token：n.toLocaleString('en-US')
  - 百分比：(v * 100).toFixed(1) + '%'
  - 成本：'$' + c.toFixed(4)
  - 延迟：< 1000ms 显示 ms，否则显示 s
  - 时间：new Date(iso).toLocaleString('zh-CN', {...})
  - 长文本：超过 100-200 字符截断 + "展开全文"按钮

==================== 测试验证 ====================

场景测试：

[场景 A] Human 消息
  1. 在 channel 中发送普通文本消息
  2. 点击时间轴节点展开
  3. 验证基础信息区块显示
  4. 验证关联信息区块显示（如有 mentions/references）

[场景 B] Agent 消息
  1. @mention Agent 触发自动响应
  2. 等待 Agent 回复完成
  3. 点击 Agent 消息节点展开
  4. 验证基础信息区块
  5. 验证 Agent 执行区块（模式、状态、时长、thinking、工具调用）
  6. 验证性能指标区块（tokens、缓存、延迟、成本）
  7. 验证数字格式化正确（千位分隔符、百分比、成本）
  8. 测试 thinking 的"展开全文"功能
  9. 测试工具调用列表的状态图标

[场景 C] System 事件
  1. 触发系统事件（断开 WebSocket）
  2. 点击系统事件节点展开
  3. 验证系统事件区块（type、level、message、metadata）
  4. 验证 metadata JSON 格式化
  5. 如果是 error 级别，验证 stack trace 显示

[场景 D] 编辑消息
  1. 发送一条消息
  2. 编辑该消息内容
  3. 点击消息节点展开
  4. 验证编辑历史区块
  5. 验证显示编辑时间、编辑者、历史内容

UI 检查：
  - 展开内容在卡片内部（不是下方独立区域）
  - 使用 border-t 分隔线，无 bg-black/30
  - 展开/收起动画流畅（约 200ms）
  - 响应式布局正常（桌面、平板、移动）
  - 长文本不溢出或破坏布局

数据检查：
  - 所有字段值与后端数据一致
  - 时间戳格式正确（本地时间）
  - Token 数量、成本计算正确
  - 百分比计算正确（缓存命中率）
  - 空值不报错，对应区块不显示

回归测试（必须执行）：
  - 时间轴筛选功能正常（按类型、时间范围、搜索）
  - 时间轴分组功能正常（today、yesterday、thisWeek、older）
  - 点击消息节点能正确跳转
  - WebSocket 实时更新正常
  - 现有系统事件展开功能正常
  - 滚动列表流畅无卡顿
