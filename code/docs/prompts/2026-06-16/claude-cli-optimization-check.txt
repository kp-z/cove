Claude Code CLI 集成优化检查 Prompt

==================== 任务 ====================

检查当前 Claude Code CLI 的生成和调用方式，参考最佳实践（调研报告），识别差距并提出改进建议。

==================== 调研报告核心发现（参考） ====================

Claude Manager 使用 Claude Code CLI 的 6 大能力：

[1] CLI 调用方式
  - 输入格式：--input-format stream-json
  - 输出格式：--output-format stream-json
  - 权限处理：--dangerously-skip-permissions（自动批准所有工具）
  - 执行模式：本地、Docker 容器、SSH 远程

[2] Tool 能力
  - 所有内置 Tool 自动可用（Read/Write/Bash/Grep/Edit）
  - 通过 --dangerously-skip-permissions 自动批准
  - 无需额外配置

[3] Skill 能力
  - 不通过 CLI 参数传递
  - 依赖项目目录 .claude/skills/ 或全局 ~/.claude/skills/
  - Claude CLI 自动扫描加载

[4] MCP 能力
  - 通过自定义 MCP 服务器（permission_mcp.py）实现权限代理
  - MCP 配置动态生成
  - 使用 --mcp-config + --permission-prompt-tool mcp__permission_approval_prompt
  - 风险：仅本地模式可用（Docker/SSH 无法回调宿主机 API）

[5] 多轮对话实现
  - 核心机制：
    1. 创建 asyncio.Queue 消息队列
    2. stdin_writer 协程从队列取消息写入 stdin
    3. stdout 解析器监听 "result" 消息（轮次结束）
    4. 队列为空 + result 触发 → 关闭 stdin → 进程退出
  - 后续消息：queue.put_nowait({"text": "..."})

[6] 关键技术点
  - 进程管理：asyncio.create_subprocess_exec + PIPE
  - 协议解析：NDJSON（每行一个 JSON 对象）
  - 状态捕获：session_id、tool_call、tool_result、cost_usd
  - 环境隔离：Git worktree（本地）+ Docker exec + SSH 远程执行
  - 权限代理：MCP stdio 协议 + HTTP IPC 回调
